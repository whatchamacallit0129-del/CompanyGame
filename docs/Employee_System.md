# 직원 시스템 설계 및 다음 개발 단계

## 1. 현재 확정된 직원 구조

직원 오브젝트는 직원이라는 게임 개념을 중심으로 확장한다.

예상 구조:

- 직원 (1)
  - EmployeeId — 직원 전용 영구 고유 ID
  - BoxCollider2D
  - DraggableObject2D
  - InteractableObject2D
  - 이후 EmployeeMovement, EmployeeSelection 등 확장 컴포넌트 추가

### ID 원칙

- Hierarchy의 `직원 (번호)`는 표시용 번호다.
- 표시용 번호는 현재 씬에 존재하는 직원들을 기준으로 관리한다.
- 모든 직원이 삭제되면 다음 생성은 `직원 (1)`부터 시작한다.
- Employee ID는 표시 번호와 완전히 분리한다.
- Employee ID는 삭제 후에도 재사용하지 않는 영구 고유 식별자다.
- 예: `직원 (1)` + `EMP-002386`
- 직원 이름이 바뀌어도 Employee ID는 유지한다.

## 2. 범용 GameObject ID 정책

직원에는 범용 `CompanyGameObjectIdentity`/`OBJ-...` ID를 불필요하게 붙이지 않는다.

개념별 전용 ID를 우선한다.

- 직원 → EmployeeId / `EMP-...`
- 방 → RoomId / `ROOM-...`
- 부서 → DepartmentId / `DEPT-...`
- 기계 → MachineId / `MACH-...`
- 기타 시스템 오브젝트 → 필요할 경우 범용 ObjectId 사용

이렇게 하면 개념별 데이터와 로직을 독립적으로 확장할 수 있다.

## 3. 직원 드래그 & 클릭 — 다음 개발 목표

### 목표

플레이어가 직원을 마우스로 클릭하고 드래그하여 회사 내부의 원하는 위치로 이동시킬 수 있게 한다.

기본 흐름:

`직원 클릭 → 선택 → 선택 표시 → 마우스 드래그 → 직원 이동 → 마우스 버튼 해제 → 배치`

### 1단계: 클릭/선택

- 직원 Collider를 클릭하면 해당 직원을 선택한다.
- 기본적으로 한 번에 한 명을 선택한다.
- 선택된 직원은 시각적으로 구분한다.
- 선택 상태는 직원 데이터와 분리된 선택 시스템으로 관리한다.

### 2단계: 드래그 이동

- 마우스 버튼을 누른 상태에서 직원이 커서를 따라 이동한다.
- 화면 좌표와 월드 좌표를 정확하게 변환한다.
- 이동 중에는 부드럽게 따라가도록 한다.
- 마우스 버튼을 놓으면 현재 위치에 배치한다.

### 3단계: 충돌/겹침 대응

- 직원이 많아져도 클릭 대상 판정이 안정적으로 동작해야 한다.
- 다른 직원이나 오브젝트가 겹쳐 있을 때 어떤 대상을 선택할지 명확하게 정의한다.
- 향후 방/기계/시설과의 배치 규칙을 추가할 수 있도록 이동 로직과 배치 검증 로직을 분리한다.

## 4. 권장 컴포넌트 구조

직원 전용 기능은 다음처럼 분리한다.

- `EmployeeId`
  - 직원의 영구 고유 ID만 담당
- `EmployeeSelection`
  - 선택/선택 해제 및 선택 시각화 담당
- `EmployeeMovement`
  - 드래그 및 이동 담당
- `EmployeeInteraction`
  - 향후 클릭 시 명령/상호작용 담당

각 컴포넌트는 한 가지 책임을 갖도록 설계한다.

## 5. 소프트코딩 원칙

앞으로 직원 조작 기능도 하드코딩을 최소화한다.

예:

- 이동 가능 여부 → 설정값으로 제어
- 이동 속도 → 데이터/Inspector에서 조정
- 선택 가능 여부 → 설정값으로 제어
- 이동 가능한 영역 → 별도의 배치/영역 시스템으로 관리
- 역할별 이동 제한 → 직원 데이터와 규칙 시스템으로 확장

따라서 나중에 `관리자만 이동 가능`, `특정 방에만 배치 가능`, `업무 중에는 이동 불가` 같은 규칙을 추가하더라도 기존 이동 코드를 크게 뜯어고치지 않는 것을 목표로 한다.

## 6. 향후 확장 계획

드래그 & 클릭 이후 직원 시스템은 다음 순서로 확장한다.

1. 직원 클릭/선택
2. 직원 드래그 & 배치
3. 직원 이동 가능 영역
4. 직원 역할/직무
5. 직원 상태값
6. 업무 배정
7. 방/시설과 직원 상호작용
8. 다중 선택 및 일괄 명령
9. 직원 AI/자동 이동
10. 회사 운영 시스템과 연결

## 7. 구현 시 주의사항

- Employee ID와 표시용 직원 번호를 절대 혼동하지 않는다.
- 직원 삭제 후 Employee ID를 재사용하지 않는다.
- 기존 ID 시스템을 깨뜨리지 않고 직원 전용 시스템을 확장한다.
- Unity 최신 API를 사용하여 obsolete 경고를 누적시키지 않는다.
- 명령 Agent의 오류가 발생해도 같은 `command.json`이 반복 실행되지 않도록 한다.
- 기능 추가 시 기존 직원 생성/삭제/ID 시스템에 영향을 최소화한다.

## 8. 테스트 기준

직원 이동 기능을 구현한 뒤 최소한 다음을 검증한다.

- 직원 한 명 클릭 가능
- 직원 선택 상태 표시
- 직원 드래그 가능
- 드래그 종료 후 위치 유지
- 여러 직원 중 원하는 직원만 선택 가능
- 직원 ID가 이동 전후 동일하게 유지됨
- 직원 이름 변경 후에도 Employee ID 유지
- 직원 삭제 후 새 직원의 표시 번호가 씬 기준으로 정상 시작
- Employee ID는 기존 삭제 직원의 ID와 중복되지 않음
